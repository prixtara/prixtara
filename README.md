## 1. Project Purpose

Build a premium technology-company website for **Prixtara Technologies Pvt. Ltd.** that communicates the company through its products and applied AI systems rather than through generic startup marketing.

The presentation currently establishes three major product / solution stories:

1. **AI-Vision Defect Detection System** — industrial computer vision and automated quality inspection.
2. **Existential AI** — private, on-premises emotional-support AI designed around local processing and safety-oriented features.
3. **Sambhashi** — an offline multilingual Indian Sign Language translator for inclusive banking and public services.

The website should feel like a technology company building real systems: precise, engineered, visual, and credible.

# 4. Product Portfolio

## 4.1 AI-Vision Defect Detection System

### Product positioning

An automated machine-vision inspection system intended to make quality control faster, easier to configure, and more practical for MSMEs.

### Core solution name from the presentation

**Compact Inspection Node**

### System components and capabilities

#### Controlled Conveyor

Presents each part at a consistent inspection position for reliable image capture.

#### Programmable LED Lighting

Exposes surface and shape defects clearly under optimized illumination conditions.

#### High-Speed Cameras

Captures images at up to **300 parts/minute** with no slowdown to production.

#### Vision Algorithms

Detect defects down to **0.1 mm** with **98%+ accuracy** across part geometries.

#### Automatic Sorting

Routes **OK**, **reject**, and **rework** parts to separate bins without manual handling.

### Primary differentiator: No-Code Setup

The presentation calls this the **30-Minute Advantage**.

Traditional vision-system comparison in the deck:

| Conventional / Traditional Systems | Prixtara System |
|---|---|
| 2–4 weeks setup | Under 30 minutes operator training |
| Specialist engineers | No coding needed |
| Custom coding | Shop-floor staff configures criteria |
| Expensive integration | Fast changeover between product variants |

### Additional claims from the source material

- Shop-floor operators can train the system on a new product in **under 30 minutes**.
- **No coding** is required.
- The setup is described as requiring **no engineers** and **no downtime** for the configuration workflow.
- Product variants can be switched between instantly / rapidly.
- The presentation positions this approach as making automated quality control practical and affordable for **MSMEs**.

### Visual product reference

The supplied industrial render shows a conveyor-based inspection station with:

- Camera / vision head
- Circular inspection lighting
- Conveyor track
- HMI / inspection monitor
- Pneumatic / mechanical sorting assembly
- Separate bins for Good / Defect / Rework

The rendered equipment also visibly carries the label **Q-INSPECT | MODEL S30 | MODULAR VISION SYSTEM**. This should be treated as visual reference text unless Prixtara confirms that it is the final commercial product name.

### Website content angle

**Story:** Manufacturing quality control should not require a long specialist integration cycle.

Suggested narrative sequence:

1. Manufacturing defects are costly.
2. Conventional machine vision can require lengthy setup and specialist integration.
3. Prixtara introduces a compact inspection node.
4. The part is presented → illuminated → captured → analyzed → sorted.
5. Operators can configure a new product in under 30 minutes.
6. Quality automation becomes more accessible to MSMEs.

# 13. Recommended Technical Architecture

This section is an implementation recommendation for the website, not product information from the PPTX.

## Suggested stack

- **Next.js** (App Router)
- **TypeScript**
- **Tailwind CSS** or a carefully scoped CSS architecture
- **MDX / structured content** for product content where useful
- **Framer Motion** for UI motion
- **GSAP** only for complex scroll choreography that needs timeline-level control
- **Lucide / custom SVG icons** for UI icons
- **Vercel** or equivalent production hosting

## Architectural principles

- Server-render by default where possible.
- Keep marketing content decoupled from interactive animation code.
- Build reusable sections and primitives.
- Do not hard-code product content inside animation components.
- Use typed content models.
- Optimize images and video aggressively.
- Respect `prefers-reduced-motion`.
- Maintain a clear separation between page composition, content, and UI components.

# 17. Accessibility Requirements

The website should meet a modern accessibility baseline.

- Keyboard navigation
- Visible focus states
- Semantic HTML
- Sufficient text contrast
- Captions / transcripts for meaningful video
- Descriptive alt text
- Reduced-motion support
- Interactive elements must not depend on hover alone
- Avoid text baked into images when the same information can be rendered as HTML

For Sambhashi specifically, accessibility should be treated as part of the product story, not merely a compliance section.

---

# 18. Performance Requirements

Because the design is cinematic, performance must be treated as a first-class requirement.

Target practices:

- Responsive image sizing
- AVIF / WebP where appropriate
- Lazy-load below-the-fold imagery
- Poster frames for video
- Avoid autoplaying large video on mobile unless optimized
- Split animation code by route / section
- Avoid unnecessary client components
- Keep above-the-fold JavaScript lightweight
- Use GPU-friendly transforms for motion
- Test on mid-range mobile devices, not only a high-end Mac
